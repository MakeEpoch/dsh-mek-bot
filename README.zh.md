# dsh-mek-bot

[English](README.md) · [上游 DS-Bot](https://github.com/Fei2411/DS-Bot)

MakeEpoch 的 DS-Bot 集成插件。DSH 侧边栏只增加一个 **Bot** 入口，在当前页面使用 DS-Bot 的原生 React 组件，不使用 iframe 启动另一套 DSH。

![DSH 中的原生 Bot 界面；本地假模型演示](docs/images/mek-bot.png)

## 使用

顶部导航列出 **Bot、群聊和可选的 DSH Agent**。点击切换对话，再次点击当前对话可展开或关闭详情；右上角菜单提供新建、用量、连接器和 Bot 设置。空间充足时详情与聊天并排，窄屏时在 Bot 区域内覆盖聊天区。DSH 自身侧栏保留原有的折叠和展开行为。删除当前 Bot 或群聊后自动回到可用对话，关闭相应详情与过期弹层。Bot 界面不提供退出、定时任务和 Agent 模式切换；DSH 原有的会话、插件和自动化界面仍可正常使用。

Bot 是有独立身份、职责、模型与记忆的长期助手，可以相互委派工作、建立群聊。Bot 内的 DSH Agent 入口通过 DSH 原有的工作区导航打开普通会话，不在外层增加另一个 Agent 菜单。

模型、密钥和权限来自你已有的 DSH 配置。新 Bot 默认不会主动调用模型发欢迎消息，选择模型后自行开始聊天。模型调用使用你所配置服务商的额度。

## 任务留在最初发起的 Bot

通过主 Bot 委派的任务，结果和问题都回到主 Bot。主 Bot 自行判断常规选择，必要时在当前对话询问你，回答后恢复同一个子任务。你直接找其他 Bot 的对话仍保持独立。委派不会再要求你去子 Bot 的窗口继续交流，群聊发帖也会自动请求回报。

子任务返回后等待验收，负责人可以要求同一任务返工、检查验证证据，未解决的工作和问题会阻止任务被接受。负责人对话中的可折叠任务摘要显示执行者、问题、结果和取消操作。真实工具授权和安全凭据卡也显示在这里，Bot 不能替用户批准操作，也看不到凭据值。

任务归属、待决问题和待发送结果保存在 `mek-bot/state.json`。重启后保留等待状态，送达情况不确定的消息会先核对收件箱及持久历史；历史不可读时保留“不确定”，不盲目重做。任务归属从新的委派开始生效，不会擅自重新归类旧的上游委派。协调层只由 `mek.js` 安装，保留的上游入口仍采用原有行为。

## 团队协作与复用

在 **Bot 设置 → 团队概况** 中集中查看任务历史、重要动态、执行策略、项目事实和复用流程。

- **主助理知情**：在团队设置中选择主助理，按 Bot 开关摘要共享。默认共享明确登记的任务摘要；普通进展不调用主助理，阻塞、失败或需要用户决定时发送去重通知。部门直聊的负责人不变，不读取其他 Bot 的私聊原文。关闭通知仍可查询摘要；关闭共享后主助理不能继续查询该 Bot 的摘要，已经送达的历史无法撤回。
- **可靠交付**：状态和待发送消息一起持久化。群聊委派持续跟踪每个成员，追问、授权、延迟结果和返工回到原负责人；失败、取消和不确定状态不能被当作成功验收。带验收标准的任务需要逐项通过并提供证据，任务面板可查看来源会话中的文本、图片和文件。
- **执行策略**：为每个 Bot 设置通用、编程或自定义职责及禁用工具；任务可设置并发、返工次数、期限和 token 预算。预算在下一次模型请求及工具调用前检查，正在生成的回复可能超过限额；不估算未提供的服务商价格，缺失用量保持未知。
- **资源协调**：已识别的工作区写入、浏览器和显式绑定的账号工具先取得独占使用权。过期但未确认释放的资源仍显示占用。它是协作约束，不能隔离任意 shell、后台进程或未接入的外部客户端；需要真正隔离时使用独立工作区和账号。
- **项目事实**：由用户创建共享范围，成员主动提交带来源和版本的事实；冲突待负责人核实，保留旧版本，可设置失效时间。不会自动汇入私聊记忆或凭据。
- **复用流程**：保存输入、指令和验收标准，先运行验证任务并接受结果，再启用该版本；更新产生新草稿。执行通过原有任务协调器，定时触发复用 DSH 自动化，不新增 Bot 定时任务菜单。
- **浏览器观察与接管**：观察已经打开的 Bot 浏览器，在面板中显式接管和归还；人工接管期间 Bot 输入暂停。仅观察不会新建浏览器。该功能需要可用的浏览器能力；密码框在截图中遮盖，操作文本不写入任务记录。

自动化验证采用本地脚本模型，不代表真实模型必然正确理解业务或通过验收；任务仍保留证据和未解决问题供核查。

## 安装

已验证 DSH **0.2.2-alpha.2**、Node.js 24 和当前 Chromium。浏览器需要支持 CSS `@scope`。

```sh
cd ds-bot
npm ci
npm run build
npm pack --ignore-scripts
dsh plugin --profile web add -w ./dsh-mek-bot-0.2.4.tgz
```

启用 bundle 后重启 DSH，不要同时启用原 `ds-bot` bundle。生产安装必须使用打包文件，禁止 `link:`、符号链接或直连开发源码。profile 保持 `autoInstallPeers: false`；宿主 API 由 DSH 加载器提供，不能安装第二份 Cordis、scope、tools 或 LLM 核心。

浏览器功能随包提供可选 Playwright 依赖；启用前需本机 Chromium/Chrome。Linux 示例（按实际安装路径调整）：

```yaml
- id: mek-bot
  config:
    browserPlugin: refs
    browserHeadless: true
    browserExecutablePath: /usr/bin/google-chrome
```

服务重启会关闭进程内浏览器。登录资料保留在各 Bot 独立目录；等待交接的任务会明确转为阻塞并回报负责人，需确认后重开，不会自动重复网页操作。

## 数据与配置

团队数据默认在 `DSH_HOME/mek-bot`，与上游的 `DSH_HOME/bot` 分开；聊天历史仍由 DSH Session 服务保存，卸载不会删除这些数据。可在当前用户的 `cordis.patch.yml` 中设置：

```yaml
- id: mek-bot
  config:
    mainName: 小音
    mainRole: 主助手
```

插件不改 DSH 源码、全局搜索、预设或原生聊天设置。团队工具只对团队拥有的会话生效。Bot 的 CSS、弹窗、DOM 读取与坐标限定在自己的面板内，不替换浏览器全局对象，不重复加载其他 DSH 插件。群聊记录从持久化 Session 日志分页读取，不依赖给模型看的有限上下文日志。

## 开发与合并上游

保留上游目录、Apache 许可证与公开 Git 历史，基线见 [.makeepoch/upstream.json](.makeepoch/upstream.json)。主要适配位于 `ds-bot/mek.js`、`ds-bot/src/client/mek/` 和团队工具注册辅助函数；原有共享 UI 保持原位，复用组件及控制器。

```sh
cd ds-bot
npm ci
npm run harness
npm run build
npm test
node scripts/build-client.mjs --check
npm run lint
```

详见[项目特点、上下游差异与文档维护要求](docs/fork-vs-upstream.md)、[集成边界与合并流程](docs/makeepoch-integration.md)和 [UI 测试方案](docs/dev/mek-ui-testing.md)。新增功能或改变使用流程时，必须在同一改动中同步更新文档。开发依赖独立安装在 `ds-bot/dev/harness`。保留的桌面、Docker 代码是上游参考资料，不是本插件的发布入口；原文见 [README.upstream.md](README.upstream.md)。
