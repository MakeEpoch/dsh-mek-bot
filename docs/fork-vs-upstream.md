### 本次合并保留或修正的下游行为

| 对象 | 最终处理与原因 |
|---|---|
| 群聊原生历史分段 | 上游 `v0.2.5` 起群聊自有 Session 会在目录变化时切到新分区（`room.sessionId` 前进，`room.id` 保持首段）。本项目原生面板原先固定读 `room.id`，分段后看不到新历史；已改为读 `store.sessionOfRoom(room)` 的当前分区，并用 `room.parts` 串起“旧分区 → 当前分区”的完整链，cursor 由 `{beforeSeq}` 扩展为 `{part, beforeSeq}`。旧的裸数字 cursor 与 `{beforeSeq}` cursor 仍按当前分区解析，不会失效 |
| 群聊公告与任务派发 | 上游只唤醒成员帖点名的成员。本项目 `mek-coordination` 的任务派发需要在“无人点名”时仍能下发，因此显式区分委派与公告：Main Bot 和本群管理员按群模式叫人，明确目标优先；全员提及保留其权限和选人规则。普通成员不带 `@` 的公告仅写群记录，不创建任务、不回流失败通知；群修订沿用正式任务归属 |
| 团队工具注册 | 上游改为 `rt.teamTools` 收集 + 按 Bot 会话注册。合并时 `tools.js` 等文件的 `registerTeamTool` 包装退化为未使用的 import，已清理；保留下游仍在使用该包装的模块（`mek-safe.js`、`mek-coordination.js`、`mek-team.js`）不受影响。普通 DSH 会话依然拿不到团队工具 |
| 分段 Session 的历史读取 | `mek-room-chat.js` 的返回体补充 `sessionId`，与 `chatPage` 一致，便于调用方判断当前分区 |
| 包身份与依赖 | 继续保留 `dsh-mek-bot`、入口 `mek.js`、`./upstream` 导出与 `dev/harness` 的 DSH `0.2.2-alpha.2` + React `18.3.1` pin；不随笔跟随上游 DSH 版本号 |

## 当前基线之后的下游修正（2026-10-31）

- 任务闭环：缺结构化报告的返回结果显示“待补报告”，齐全后显示“待验收”；混合执行、阻塞和决策状态不伪装成完成。继续要求负责人明确验收与有效证据。
