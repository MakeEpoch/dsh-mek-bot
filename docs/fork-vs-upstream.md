### 合并及验证记录（2026-10-31）

- 基线：上游 v0.2.3（`4a7b550`）→ v0.2.4（`f823773`）；合并前下游 `31d5a84`。
- 初次冲突涉及 README、包与锁文件、生成客户端、harness、browser-pane、overlays、sidebar 和工具注册；后续按实际调用链复核原生 UI，而非只消除冲突标记。
- 实测：
  - 合并后 `npm run build` 通过，`npm test` **1314 通过 / 1 失败**
  - 纯净 `v0.2.4` 基线（需先 `npm run harness`）：**1223 通过 / 0 失败**
  - 上述为初次合并记录。复核确认存在原生 UI 回归：顶部导航混入独立侧栏的布局与账户页脚，窄屏详情被错误折叠；不能将主 Bot 缺失一概归因于 JSDOM。
- 原生 UI 修正后的验证：
  - 全量测试 **1370 通过 / 2 跳过 / 0 失败**；本地 mock 服务测试需要允许回环端口监听。构建一致性检查通过，lint 通过但存在警告。
  - 生命周期测试恢复“主 Bot 位于 header 内”的断言，覆盖 900、700、390、0、1200px 的容器尺寸变化与详情显示。
  - 真实 Chrome 使用最新 client.js 和本地 mock 页面验证：900px 并排详情；700/390px 覆盖详情；宿主侧栏开合使插件区域在 700/884px 间变化时自动调整布局；聊天区左边距为 0，账户页脚不存在，无页面异常。
  - Chrome 验证使用隔离的宿主布局夹具，未替换用户正在运行的 DSH 安装副本，不代表该安装已更新。
  - 后续安装前验证：冻结的 `dsh-mek-bot@0.2.4` tgz 安装到独立 profile，在实际 DSH `0.2.2-alpha.2` 中通过 Bot 创建、模型选择、委派和群聊回复；协作闭环通过用户决策、恢复、返工、证据检查和验收；团队策略、摘要通知、知识冲突与历史、工作流草稿和预算冒烟通过。
  - 同一隔离 DSH 的真实 Chrome 检查确认顶部 Bot 导航、详情面板、宿主侧栏开合、聊天区左边距为 0，未出现 Bot 独立侧栏或账户页脚。此次发现并修正两个冒烟脚本混用 Bot 身份 ID 与运行会话 ID 的断言；运行时任务归属保持原语义。此记录仍不等于正式安装副本的浏览器验收。

## 当前基线之后的下游修正（2026-10-31）

- 任务闭环：缺结构化报告的返回结果显示“待补报告”，齐全后显示“待验收”；混合执行、阻塞和决策状态不伪装成完成。继续要求负责人明确验收与有效证据。
- 补报与恢复：新结果自带处理指引，旧的未关闭结果向原委派方发送一次持久化提醒，复用已有返工机制。不会只因缺报告取消，不自动重跑外部操作、不补造报告。
- 对话状态与交互：修正 scene portal 吞掉本地挂载目标的问题，恢复当前 Bot 在聊天末尾的临时执行状态，不写入历史；补齐 `show_view` 待回答卡，并通过公开 `uiSession.sessionStatus` 接收当前会话的 question/plan-review 回调。提交失败可重试，其他未公开的宿主面板请求不保证兼容。
- 权限接入：详情读取当前 DSH Session 的实际权限，提供跳转到对应原生会话的设置入口；选择及自动审查风险确认由 DSH 处理。Bot 跨会话预设单独折叠，保留三档与原传播规则，不将 `auto` 设为新会话默认值；未嵌入宿主权限 slot。
- 任务列表：聊天区支持整体收起/展开并显示数量，当前标签页按 Bot 记忆选择；授权和凭据卡不随列表隐藏，完整历史仍位于团队概况；更多任务入口限定在列表的居中底部，统一按钮样式并显示剩余数量。
- 以上是本项目修正，不属于上游 v0.2.4 新增内容；验证范围记录在本次变更及 UI 测试记录中。

## 后续版本如何记录

每次合并在本文顶部新增版本节，并更新版本总览和 `.makeepoch/upstream.json`，旧版本保留历史状态。每个版本至少记录：

1. 上游 tag、commit、发布日期，以及本项目合并提交和合并前基线。
2. 按能力对照“上游变更 / 本项目采用、适配、不采用或待验证 / 理由和环境限制”。
3. 被保留或修正的下游行为；涉及当前用法时同步修改 README，不能只追加历史记录。
4. 实际构建、自动测试、Chrome、隔离 DSH 和安装包验证的版本、范围及未知项，不把组件或 mock 通过写成正式安装或业务验收。

升级从下游 main 建立更新分支，先保存工作区和合并前基线，再 fetch 并核对目标 tag；正常 merge 保留上游谱系，不用 `-X theirs` 整体覆盖。按最终源码重建客户端和锁文件，运行检查；区分上游原有、下游已有和本次合并引入的问题。具体命令与边界见[集成文档](makeepoch-integration.md)，界面验收见 [UI 测试方案](dev/mek-ui-testing.md)。合并与测试本身不代表已获准 push 或替换正在运行的安装。

## 文档必须随功能维护

项目当前能力以中文版 [README](../README.md) 为主；本文只维护版本吸收及合并记录。新增功能、调整交互或能力限制、持久化格式变化、上游升级引入或删除能力，都必须在同一改动中更新对应文档。

| 改动 | 必须核对并更新 | 至少说明 |
|---|---|---|
| 新功能或现有能力变化 | 根 README；同步包内 `ds-bot/README.md`，旧语言入口保持跳转 | 用户入口、流程、结果、上下游归属、限制及验证状态；包内链接应适用于独立安装 |
| 接入、工具作用域、存储、权限或依赖变化 | `makeepoch-integration.md`；受影响的 `docs/plans/` 设计 | 宿主和插件职责、数据兼容、失败和恢复行为 |
| UI、导航、弹层、响应式或生命周期变化 | README、`dev/mek-ui-testing.md`，必要时 `design/ui-standard.md` | 操作步骤、宽窄屏及状态覆盖、可观察验收标准与证据 |
| 合并上游或升级 DSH | 本文版本记录、`.makeepoch/upstream.json` 及受影响文档 | 来源、采纳判定、保留的下游行为、检查结果和待验证项 |
| 安装、构建或验证方式变化 | README、贡献指南及开发文档 | 当前可执行命令、前置条件、停止和清理方式 |

纯文档改动核对链接、代码依据、根/包内副本与状态一致性，无需重跑模型或 UI 套件。修复恢复既定行为时可补回归用例和验证记录，但过期说明仍应纠正。不要将同类能力都称为 fork 独有，不把上游测试结论或代码存在推导为本项目验收。

本规则同时见 [AGENTS.md](../AGENTS.md)、[贡献指南](../CONTRIBUTING.zh.md)和 [PR 模板](../.github/pull_request_template.md)；当前没有自动判断“文档是否完整”的 CI 门禁，仍需审查核对。
