## 插件间边界

Bot 插件通过 Cordis 公开服务机制提供可选 `mekBotBridge` v1。接口只提供候选身份、解析当前 Session、提交用户消息、停止及订阅可见文本；不暴露团队完整状态或任意工具执行。

- 候选为现存 Bot 群和 Main Bot。普通 Bot 不可关联；服务端每次解析、收发、停止均重新检查身份，删除或撤销 Main 身份后失败，不转到其他 Bot。
- 稳定身份用于绑定，每次消息解析当前会话段，换段不会导致新建普通微信会话。
- 私聊只关联 Main Bot；Pad 的 `@chatroom` 群只关联 Bot 群。扫码微信不支持群。设置保存、运行时使用都检查类型。
- 入站仍先经过现有访问控制、去重、群提及规则和消息合并。关联是路由选择，不是绕过白名单的许可；关联变化使尚未提交的旧消息失效。
- 出站只发主 Bot 的用户可见回复和群成员正式文字，不回显用户输入，不发推理、隐藏 Bot 回合或系统事件。复制到微信的群发言带成员名字。
- 关联、改绑、解绑不创建新的 DSH Session；普通微信会话索引不接管 Bot 的 Session，旧普通会话历史保留。关联时取消旧普通微信输出的待发缓冲，避免混入新的关联对话。
- `/stop` 只停止关联身份；已关联聊天的 `/new`、`/reset` 不重置 Bot，提示到设置解绑。私聊关联从 0.2.10 / 0.1.10 起沿用微信聊天的排队/打断设置，取消当前私聊轮次后重新解析逻辑身份并提交；群消息仍排队，不扩展为群全部中断。
- 授权、密钥和交互卡仍在 DSH 处理；本轮没有实现跨端卡片答复、上游八平台接入或微信自动配对。

## 持久化和界面

WechatPad 在自己的 `wechatpad/bot-links.json` 保存版本、修订号和绑定；原子替换，拒绝旧修订覆盖，未知/损坏格式不可静默覆盖。凭据继续由原连接管理，不复制到 Bot 插件。

按维护者后续要求，入口移到主 Bot / Bot 群右侧详情的设置中：主 Bot 选择私聊用户，Bot 群选择微信群；无需输入 ID 后缀来发现群功能。微信设置的会话页改为关联汇总与入口说明，原有连接/访问控制仍在微信插件中。关联独立保存并立即生效，旧记录无须迁移。

发送结果不确定时不自动重放；当前进程去重可见事件，重启不读取旧消息向微信补发。目标失效、发送失败可观察，解绑后不重播历史。真实平台附件回传、跨端审批和服务重启期间的可靠出站队列不属于本轮交付。

## 右侧设置与聊天发现（0.2.9 / 0.1.9）

WechatPad 提供可选公开服务 `wechatBotLinks` v1，Bot 通过注入子作用域读取该服务，生命周期结束时清除引用。Bot API `mek-wechat-view/update` 只接受已存在的 Main Bot 或 Bot 群，更新还需可写团队。服务按目标返回：无凭据连接状态、符合目标类型的已发现聊天、该目标的绑定及修订号。修改时重新验证身份、聊天类型、修订和当前归属，不能从此处抢占其他目标的绑定。

可用性分层显示：插件未安装/未启用，接口版本不兼容，服务启动中，以及每个连接的未启用、配置不全、未扫码登录、连接中、已断开、异常和可用。不可用时保留既有绑定；连接就绪且相应聊天类型未关闭才能新建，断开时仍可解除已有绑定。访问白名单不被关联操作修改，iLink 沿用现有独立扫码/启用语义，不继承 Pad 私聊白名单。

用户可选择 WechatPad 或微信机器人（iLink）的已发现私聊；Bot 群仅显示 WechatPad 群。独立聊天目录在收到有效入站消息时记录（即使因白名单或未 @ 而未调度），自发回声、空内容及系统事件不记录。目录只保存 provider、chatId 和可用名称，原子存储到 `wechatpad/known-chats.json`，最多 1000 项；不保存消息正文、账号令牌或 iLink 回复 context token。历史普通会话、现存绑定和已发现群也参与候选合并。空列表提示先向所选账号/机器人发消息，再刷新；已知 ID 仍可手动输入。

## 输入状态、打断与真实队列修复（0.2.10 / 0.1.10）

微信机器人配置已允许输入状态，但此前普通投递和 Bot 关联都没有触发底层 typing 接口；关联还强制 queue，绕过已保存的 interrupt。现以 WechatPad 所有的每聊天状态租约处理开始/续期/结束，普通路由跟随真实投递轮次，关联路由仅向 Bot 查询当前私聊是否忙碌的布尔值，不读取内部工具、隐藏消息或推理。解绑、停止、目标失效、服务释放及配置禁用会释放租约；异步旧状态不能释放新租约，信号失败不阻塞消息。群工作不冒充私聊输入状态。

私聊打断由 Bot 自己执行取消和重新解析，保留宿主已有待处理消息，群目标拒绝打断模式。原生界面通过公开 `sessions.retain` 和 `inbox` projection 订阅实际 next-turn/next-step 队列；仅展示用户来源，操作复用 `updateQueue` 的 steer/remove，换段/切换会话释放引用。上游独立窗口不注册此原生组件。
