# 上游能力复用与 WechatPad 关联

日期：2026-11-05。维护者要求优先复用完善的上游实现，保持当前原生界面入口；IM 在 WechatPad 内扩展，不启用上游 IM 平台模块。

## 重叠能力的取舍

比较基线为本地 `1b79bb5`、上游 v0.2.7 `71d344b` 和 dev `1f5b21a`。同名版本不代表已吸收同一上游源码。

上游 Goal 源码及上游独立入口保留，便于后续跟踪；`coordinateTasks` 原生入口跳过其运行时，界面不出现无对应服务的“设定目标”。普通 `/goal` 的提示由入口能力决定。

## 插件间边界

Bot 插件通过 Cordis 公开服务机制提供可选 `mekBotBridge` v1。接口只提供候选身份、解析当前 Session、提交用户消息、停止及订阅可见文本；不暴露团队完整状态或任意工具执行。

- 候选为现存 Bot 群和 Main Bot。普通 Bot 不可关联；服务端每次解析、收发、停止均重新检查身份，删除或撤销 Main 身份后失败，不转到其他 Bot。
- 稳定身份用于绑定，每次消息解析当前会话段，换段不会导致新建普通微信会话。
- 私聊只关联 Main Bot；Pad 的 `@chatroom` 群只关联 Bot 群。扫码微信不支持群。设置保存、运行时使用都检查类型。
- 入站仍先经过现有访问控制、去重、群提及规则和消息合并。关联是路由选择，不是绕过白名单的许可；关联变化使尚未提交的旧消息失效。
- 出站只发主 Bot 的用户可见回复和群成员正式文字，不回显用户输入，不发推理、隐藏 Bot 回合或系统事件。复制到微信的群发言带成员名字。
- 关联、改绑、解绑不创建新的 DSH Session；普通微信会话索引不接管 Bot 的 Session，旧普通会话历史保留。关联时取消旧普通微信输出的待发缓冲，避免混入新的关联对话。
- `/stop` 只停止关联身份；已关联聊天的 `/new`、`/reset` 不重置 Bot，提示到设置解绑。现阶段关联消息固定排队，普通微信会话的打断选项不扩展为群全部中断。
- 授权、密钥和交互卡仍在 DSH 处理；本轮没有实现跨端卡片答复、上游八平台接入或微信自动配对。

## 持久化和界面

WechatPad 在自己的 `wechatpad/bot-links.json` 保存版本、修订号和绑定；原子替换，拒绝旧修订覆盖，未知/损坏格式不可静默覆盖。凭据继续由原连接管理，不复制到 Bot 插件。

入口为既有“设置 → 微信 → 会话”的“Bot 关联”卡，不增加新的全局设置页。关联独立保存并立即生效，原有连接/会话/访问控制页保持位置。Bot 侧继续使用顶部会话导航、右侧详情/待办/任务/浏览器。

发送结果不确定时不自动重放；当前进程去重可见事件，重启不读取旧消息向微信补发。目标失效、发送失败可观察，解绑后不重播历史。真实平台附件回传、跨端审批和服务重启期间的可靠出站队列不属于本轮交付。

## 验证

按 UI 测试方案区分单元、生成 bundle、隔离 DSH、真实浏览器与真实微信验收。隔离环境使用独立 `.dsh-test-*`、本地脚本模型和模拟微信适配器，禁止访问正式 DSH_HOME 或真实账号。最终执行记录见 UI 测试文档。
