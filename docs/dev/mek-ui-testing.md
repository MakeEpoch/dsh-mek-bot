# dsh-mek-bot UI 测试方案

- 适用对象：本 fork 的原生 DSH 插件；独立桌面端和移动端不是本方案的发布目标。
- 相关约束：[项目特性与差异](../../README.md)、[版本记录与维护要求](../fork-vs-upstream.md)、[集成边界](../makeepoch-integration.md)、[界面规范](../design/ui-standard.md)。
- 本文件是执行方案。下文“应通过”表示验收标准，不表示用例已经执行；实际结果单独按第 7 节记录。

## 1. 按改动选择验证范围

| 改动 | 自动检查 | 真实浏览器 | 隔离 DSH / 安装包 |

| 纯文档 | 链接、源码依据、根/包内 README 与状态一致性 | 无需 | 无需 |

| feed、任务协作、权限、群聊、存储 | 同上，补相应 host/mock 冒烟 | 状态变化和失败/恢复流程 | 对应业务流程与持久化恢复必须执行 |

## 2. 三层验证各自证明什么

### A. 自动组件与生命周期检查

从仓库的 `ds-bot/` 目录执行。依赖已安装时无需重复安装；首次准备使用 `npm ci`、`npm run harness`。

```sh
npm run build
node --import ./test/harness-resolve.mjs --test \
  test/mek-adapter.test.js \
  test/mek-dom.test.js \
  test/mek-delete-lifecycle.test.js \
  test/sidebar-switch.test.js \
  test/frame-layout.test.js \
  test/right-panel.test.js \
  test/side-panel.test.js
npm test
node scripts/build-client.mjs --check
npm run lint
```

这些测试覆盖注册入口、DOM/弹窗隔离、尺寸状态、详情关闭、焦点退役和删除后的会话恢复。JSDOM 不计算真实布局，必须显式提供容器尺寸；测试不能将“主 Bot 位于 header 中”放宽为“场景中任意位置存在”。像素、遮挡、滚动和 CSS 实际效果由后两层验证。

部分 host/Office/mock 测试需要本地服务及额外依赖。出现端口监听权限或依赖错误时，记录原因，在允许的隔离环境重跑；不要删除断言或把未匹配、跳过写为成功。

### B. 真实浏览器中的受控宿主夹具

使用最新构建的 `client.js`、真实 React/ReactDOM 和本地 mock API。页面提供一个具有固定高度、可调宽度的宿主区域及可开合的模拟侧栏。通过插件真实 `apply()` 注册的 main 组件挂载，不能换成重画的静态 HTML。

夹具必须能：调整 Bot 区域宽度而不触发窗口 resize；模拟列表增删、消息、请求失败和恢复；记录页面异常；检查父页面 style/data 与注册入口。测试者通过按钮和输入完成流程，DOM 几何读取用于核对结果，不代替点击、输入和实际截图。

2026-10-31 的 sidebar 修复使用过临时 Chrome 夹具，**仓库当前没有一个已收录的单命令浏览器夹具 runner**。临时文件路径不能当成长期执行入口。复用夹具时应保留页面源码、启动方式、mock 数据及实际使用的 bundle 哈希；若新增持久 runner，需同时更新本节和 CI 说明。在 runner 收录前，可直接使用 C 层隔离 DSH 完成真实浏览器验证。

### C. 真实 DSH 与候选安装包

在独立 `.dsh-test-*` 数据目录和空闲端口启动 DSH，只安装待测 `dsh-mek-bot` 包，以本地 mock 模型验证实际 slots、会话、权限、历史、feed 和相邻插件。保留默认宿主组件，禁止用上游全局接管界面替代原生插件。

发布候选必须从打包文件安装，记录 tgz SHA-256，并核对安装目录中实际 `client.js` 的 SHA-256 与待测产物一致。源码构建成功与用户正在运行的安装副本已更新是两个不同状态。此层测试仍不包含对用户正式 DSH 的部署授权。

## 3. 准备隔离 DSH 环境

### 身份和依赖核对

1. 从 `.makeepoch/upstream.json` 记录上游 commit；从 `ds-bot/package.json` 记录插件版本；从 `ds-bot/dev/harness/package.json` 读取 DSH pin。以当前文件为准，不直接照搬旧截图或上游 README 的版本。
2. 检查测试所用 DSH 实际版本与 pin 一致，记录 Node、Chrome/Chromium、React 版本与操作系统。`DSH_HARNESS` 若指向别处，也记录其位置及版本。
3. 使用本地脚本模型和假数据。外部浏览器、文件、连接器用本地夹具；没有能力时验证明确的不可用状态，并标记真实能力流程未验证。
4. 选择空闲 web/mock 端口，例如 3186/8786；不要占用正式服务端口 3080。所有测试数据、日志、浏览器 profile 均留在独立测试目录。

### 安装和启动步骤

以下是手动搭建步骤，需有可工作的本地 DSH CLI、pnpm 和依赖。它不是已经实现的自动测试脚本，本次仅核对命令及配置入口，未重新启动整套 DSH。

在仓库 `ds-bot/` 目录中：

```sh
export BOT_UI_REPO="$(git rev-parse --show-toplevel)"
export BOT_UI_HOME="$(mktemp -d "$BOT_UI_REPO/.dsh-test-ui-XXXXXX")"
export BOT_UI_DSH="$BOT_UI_REPO/ds-bot/dev/harness/node_modules/.bin/dsh"
npm run build
npm pack --ignore-scripts --pack-destination "$BOT_UI_HOME"
export BOT_UI_PACKAGE="$BOT_UI_HOME/dsh-mek-bot-$(node -p "require('./package.json').version").tgz"
sha256sum "$BOT_UI_PACKAGE" client.js
DSH_HOME="$BOT_UI_HOME" "$BOT_UI_DSH" --profile web --dump-config \
  > "$BOT_UI_HOME/initial-config.local"
```

上一步只初始化隔离 profile 并将合成配置保留在本地。**安装插件前**，检查该测试 profile 的 `pnpm-workspace.yaml`，设置 `autoInstallPeers: false`，保留其他已有字段。随后安装：

```sh
DSH_HOME="$BOT_UI_HOME" "$BOT_UI_DSH" plugin --profile web add -w "$BOT_UI_PACKAGE"
```

安装后检查 **测试目录** 的 `profiles/web/`：

- `package.json` 中保留默认宿主 bundles，加入 `dsh-mek-bot`；不能同时启用原 `ds-bot`。
- `pnpm-workspace.yaml` 保持 `autoInstallPeers: false`，不向 profile 补装另一套 Cordis/tools/LLM 核心。
- 插件 patch 的 ID 为 `mek-bot`，包和 bundle 名为 `dsh-mek-bot`；不要沿用上游 `id: bot`、包名 `ds-bot`。
- 核对安装目录中的实际入口为 `mek.js`，实际客户端产物与上面记录的哈希一致。仅改依赖清单不表示 bundle 已启用。

在另一个终端中设置与上面**相同**的 `BOT_UI_REPO`、`BOT_UI_HOME`，前台启动 mock：

```sh
cd "$BOT_UI_REPO/ds-bot"
MOCK_PORT=8786 MOCK_LOG="$BOT_UI_HOME/mock.jsonl" MOCK_LOG_TOOLS=1 MEK_MOCK_COORDINATION=1 \
  node dev/mock-llm.mjs "$BOT_UI_HOME"
```

在原终端前台启动测试 DSH：

```sh
DSH_HOME="$BOT_UI_HOME" \
DEEPSEEK_BASE_URL=http://127.0.0.1:8786/v1 DEEPSEEK_API_KEY=mock-key \
  "$BOT_UI_DSH" --profile web --no-open --port 3186 \
  > "$BOT_UI_HOME/web.log" 2>&1
```

`mock-key` 仅是本地 mock 的占位值。在本机私下打开启动日志中的认证 URL，不把 URL 中的 token、cookie、完整认证日志提交到仓库或贴入报告。确认模型路由指向本地 mock 后再发消息；不能连接时先诊断 profile、模型路由和本地端口，不改用真实付费模型凑结果。

上游 `dev/bench.sh` 仍按 `ds-bot` bundle 与 `id: bot` 配置。未经下游适配及入口核对，不得将它的一次成功启动写成原生插件验收。`dev/mek-smoke.mjs`、`mek-coordination-smoke.mjs`、`mek-team-smoke.mjs`、`mek-workflow-smoke.mjs` 提供业务检查，但不负责创建这个原生 UI 环境；使用前读取各脚本参数和所需场景，不能把 API 冒烟当成点击验收。

任务 owner 使用运行会话标识；冒烟断言应使用 Bot 的 `sessionId`（没有时回退 `id`），不能将 Bot 身份 ID 与会话 ID 混用。不要额外保存带 token 的浏览器启动 URL；测试认证只使用隔离环境正常提供的入口，日志留在本地。

## 4. 宽度和状态矩阵

测量的是 `.mek-bot-scene` 的可用宽度，不能只记录浏览器窗口宽度。

| 条件 | 重点 |
|---|---|
| 1200、900px | 导航在顶部；聊天无额外左栏占位；详情可并排 |
| 740px 边界及其两侧（739/740/741） | 当前详情最小宽度 320px + 聊天最小宽度 420px；切换平稳，详情状态不丢。阈值以 `frame-layout.js` 当前常量为准 |
| 700、390px | 请求打开的详情仍可见，覆盖聊天区；面板不超出插件区域，关闭按钮可操作 |
| 初始隐藏/0px → 可见 | 首帧不丢主 Bot，恢复后重测宽度；不把 0px 误判成没有主 Bot |
| DSH 侧栏或右侧面板开合 | 不改变窗口尺寸也能重排；不意外收起宿主侧栏或挤占其他插件 |
| 窗口连续缩放、200% 缩放、长名称与多 Bot | 无不可达控件、整页横向溢出或导航被遮挡；列表允许自身横向滚动 |
| 浅/深主题、中文/英文、减少动态效果 | 文案不截断关键操作；焦点、对比度和动效符合规范 |

核心流程至少在 900、700、390px 测试。主题、语言和键盘覆盖受影响组件，不要求将所有业务用例与全部维度做笛卡尔积。目标宿主为 DSH Web/DSH Desktop 时分别记录实际验证的宿主，不能相互代替。

## 5. 操作用例与验收标准

前置数据：一个主 Bot Chief、两个成员 Writer/Reviewer、一个群聊；至少一个长名称。测试图片使用本地 PNG，不放真实身份或业务资料。

| 编号 | 操作 | 应通过的可观察结果 |
|---|---|---|
| B01 入口与冷启动 | 打开 DSH → Bot；刷新；切到普通会话再返回 | 宿主只增加一个 Bot 入口；Bot 列表在 `.mek-team-header` 内；无 Bot 包装 iframe、第二个应用或额外外层 Agent 入口；无页面异常 |
| B02 对话导航 | 依次点击 Chief、Writer、群聊；再次点击当前项；滚动长列表 | 会话切换正确；重复点击切换详情；当前项高亮及 `aria-expanded` 与可见状态一致；新排序后仍可定位当前项 |
| B03 宿主边界 | 保持 Bot 打开，开合 DSH 左右侧栏；使用宿主侧栏快捷键；切换其他插件 | 只由用户动作改变宿主侧栏；无 Bot 带来的左边距或账户页脚；快捷键仍由宿主处理；Bot 卸载后不残留父页面样式、data 标志或监听器 |
| B04 详情和尺寸 | 打开 Writer 详情，按第 4 节调整容器宽度；关闭、重开 | 宽屏并排、窄屏覆盖；面板宽度不超过 scene；关闭按钮始终可点；不出现按钮已展开但面板未挂载；切宽后不丢选择 |
| B05 删除与跨窗变化 | 打开待删除 Bot 的详情/编辑，删除它；另一窗口删除当前 Bot；删除当前群聊 | 回到有效会话；过期面板退出且不可交互；焦点不留在 inert/aria-hidden 元素内；能继续切换和输入；无 hook 顺序异常 |
| B06 设置和入口 | 右上角更多 → Bot 设置 → 团队概况；切换各节、用量、连接器；退出设置 | 各页面可达；没有旧底部菜单或额外团队入口；Bot 自带定时任务、退出和模式切换不出现；宿主对应功能仍可用 |
| B07 恢复与重挂载 | 选择 Writer，退出 Bot 再返回；刷新；重新启动隔离 DSH | 保留约定的面板/会话选择；不存在的旧 ID 安全回退；不重复注册、不重复打开弹层 |
| B08 键盘与弹层 | Tab 遍历、Enter/Space 激活；打开菜单、方向键/Home/End、Esc；开关详情/设置 | 焦点可见、顺序合理；Esc 关闭正确层级并回到触发点；退出中的面板不可聚焦；关键控件有可访问名称 |
| B09 文本与图片 | 输入文本；粘贴/拖拽本地图片；发送；模拟失败后重试 | 附件预览及输入状态正确；发前不提交；失败保留可重试内容，重试不重复建任务；发送后附件清空；历史回读图片正确 |
| B10 委派与验收 | Chief 委派 Writer；制造常规选择/用户决策；答复；返工；验收或取消 | 问题和结果留在原负责人对话；用户回答恢复同一任务；结果与证据可查；纯文本结果显示待补报告，负责人请求补报后可进入待验收，缺失/空白证据拒绝验收；旧结果恢复只提醒一次，不重跑执行者；未完成决策/失败/不确定状态不能当作成功；直接成员聊天不混入委派状态 |
| B11 群聊 | 查看较长历史、加载更早消息、触发多成员回复、停止当前轮次 | 持久历史分页正确、身份正确；工作状态和回复随事件更新；停止/失败可观察；切聊天后仍可回来查看 |
| B12 团队功能 | 配置摘要共享/策略；提交有来源的项目事实并制造冲突；验证后启用流程 | 入口、持久化和失败提示正确；摘要不冒充私聊原文；冲突和来源可查；流程版本未通过验证时不能启用；不新增 Bot 调度菜单 |
| B13 多标签和 feed | 两个可见标签切换；隐藏/恢复一个；关闭当前 feed 持有窗口；再次导航 | 通知和状态最终补齐；其他标签仍可导航/加载；支持 BroadcastChannel 时观察流共享及持有者更替；保留网络证据，不把等待时间当成通过 |
| B14 能力、错误和产物 | 关闭浏览器/文件能力；模拟 API 失败；恢复能力；检查产物预览 | 明确显示不可用/失败，保留恢复入口；不凭空宣称可用；产物从生产会话读取；文件或网络不可读保留未知 |
| B15 浏览器接管（能力可用时） | 本地页面已打开 → 观察 → 接管 → 输入 → 归还 | 观察不新建浏览器；接管期间 Bot 输入暂停；归还后恢复；密码字段遮盖；不能操作真实网站或账号验证此用例 |

自动化应从最新页面状态选择 role/label 或明确的业务 ID。导航后更新定位信息；不要依赖列表序号或固定坐标，因为排序和动效会改变位置。等待页面状态、API 回执或明确事件，不用固定睡眠代替验收。状态和截图都要核对：按钮 aria 状态正确不意味着面板真实可见，DOM 节点存在也不意味着能点到。

### 执行状态与选择请求（B17 / B18 / B20）

- B17：发送消息后检查当前单聊末尾的思考状态，再进入工具执行；状态只保留一条，位于 `[data-chat-running]`，无新增持久消息。切换到空闲 Bot 时无串状态，返回执行 Bot 可继续显示；结束或停止后移除。覆盖纯文本流式让位规则、已滚到末尾自动跟随、上翻历史不强制滚动、窄屏可见性。
- B20：群聊发送分步长任务，核对末尾头像、动作和用时与本群成员工作源一致。成员让出发言位后状态继续更新；多成员各一行，轮次内不重复。切换私聊/其他群无串状态，完成/停止移除，历史不增加动作消息；在尾部跟随，上翻保持位置；宽屏、390px、详情开关均检查。审批只显示本群请求。
- B18：分别触发 `ask_user`、交互 `show_view`（选项及表单），即使历史中没有对应工具行也能看到待回答卡。核对选项与字段、回答和关闭、失败保留输入并可重试、成功恢复执行、刷新恢复、Bot 切换隔离；收起任务不能隐藏请求。对公开 `uiSession.sessionStatus` 的 question/plan-review carrier 验证原始问题 ID、选项、批量答复、关闭及只读 review；不得转用 Bot 提问端点或伪造主会话。未公开 carrier 的宿主请求保持未验证。

### 任务列表收起（B16）

聊天区有多条任务时点击“收起任务”：只保留团队任务与数量，隐藏任务行及“显示更多”；授权和安全凭据卡继续可见。再次展开可查看待补报告、待验收及原始结果。切到另一 Bot 后返回、退出面板重挂载或刷新，当前标签页中各 Bot 的选择分别保留；新标签页和存储不可用时仍能正常操作。超过首批 8 条时，底部“显示更多任务”使用与列表同一居中列的轻量胶囊按钮，标出剩余数量；每次追加最多 8 条，全部显示后按钮消失，不得退化为贴左的浏览器默认按钮。团队概况的“加载更早任务”复用同一按钮样式。团队概况里的完整历史不受此开关影响。宽屏/390px、键盘 Enter/Space 及 aria-expanded 与可见性都要核对。

### 当前会话权限入口（B19）
